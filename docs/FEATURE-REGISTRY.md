# Feature Registry

Machine-readable version: `pipeline/config/feature_registry.json`, generated by
`pipeline/build_feature_registry.py`. **Do not hand-edit the JSON file** — run
`python pipeline/build_feature_registry.py` instead. The generator reads
`metric_registry.json`, `settings.json`'s `fundamentals.metric_weights` and
`market_behavior.weights`, and `scorer.py`'s `LOWER_IS_BETTER_METRICS`/`RANGE_METRICS` sets,
so the registry can never silently disagree with the code that actually scores.

## What this adds that didn't exist before

`metric_registry.json` already declares formula version, units, provider preferences, and
per-metric direction for 29 metrics. What it does not have — and what the research contract
(section 9) requires — is a **usage classification**: whether a feature is a ranking signal,
an eligibility filter, a risk-control input, a confidence input, or explanatory-only, so the
same number can never be silently double-counted across two of those roles.

53 features are currently registered across 6 families: `value` (3), `growth` (2), `quality`
(24 — profitability, financial health, capital allocation, and accounting quality all roll
into this family), `momentum` (7), `catalyst` (11 — earnings-revision and surprise factors),
`risk` (3 — `low_beta`, `risk_adjusted`, `drawdown_resilience`).

## An honest gap this generator surfaces

12 of the 32 metrics actually scored in `fundamentals.metric_weights` — `peg`, `forward_pe`,
`sales_multiple`, `price_to_book`, `current_ratio`, `free_cash_flow_yield`,
`gross_profits_to_assets`, `revenue_growth`, `earnings_growth`, `earnings_surprise`,
`ev_to_ebit`, `asset_growth` — have **no entry in `metric_registry.json`'s
`metric_inventory`**. Their direction is still correct here (pulled from `scorer.py`'s
`LOWER_IS_BETTER_METRICS`/`RANGE_METRICS`, the actual scoring code, not guessed), but their
`economic_rationale` says so plainly rather than fabricating a definition:
`"Not yet declared in metric_registry.json metric_inventory."` — and each carries
`"definition_declared": false`. Closing that gap means writing 12 more entries into
`metric_registry.json`'s `metrics` block; it hasn't been done as part of this upgrade.

## A classification gap this generator also surfaces

`low_beta`, `risk_adjusted`, and `drawdown_resilience` are registered in the `risk` family,
but their `usage` honestly includes `"ranking"` — because `market_behavior.weights`
(`settings.json`) genuinely blends them into the composite score today. The brief's target
state (section 6.11) is risk-control-only unless out-of-sample evidence supports an alpha
role; that reclassification has not happened in code. Each entry carries a
`classification_gap` field stating this explicitly rather than describing an aspirational
state as though it were current behavior.

## Regenerating

```
python pipeline/build_feature_registry.py
```

Run this whenever `metric_registry.json`, `fundamentals.metric_weights`,
`market_behavior.weights`, or `research_screens_v2.py`'s weight tables change. It's
deterministic and side-effect-free (reads config, writes
`pipeline/config/feature_registry.json`).
