# 003 — Respect prefers-reduced-motion in AnimatedNumber

## Problem

`AnimatedNumber.jsx` runs a 700ms `requestAnimationFrame` count-up loop
whenever its `value` prop changes, with no check of the user's motion
preference at all:

```jsx
/* src/components/AnimatedNumber.jsx:7-37 — current */
export default function AnimatedNumber({ value, format = String, duration = 700 }) {
  const [display, setDisplay] = useState(value)
  const fromRef = useRef(value)
  const frameRef = useRef(null)

  useEffect(() => {
    if (!Number.isFinite(value)) {
      setDisplay(value)
      fromRef.current = value
      return undefined
    }
    const from = Number.isFinite(fromRef.current) ? fromRef.current : value
    if (from === value) {
      setDisplay(value)
      return undefined
    }
    const start = window.performance.now()
    const tick = (now) => {
      const progress = Math.min(1, (now - start) / duration)
      const eased = 1 - (1 - progress) ** 3
      const next = from + (value - from) * eased
      setDisplay(next)
      if (progress < 1) {
        frameRef.current = window.requestAnimationFrame(tick)
      } else {
        fromRef.current = value
      }
    }
    frameRef.current = window.requestAnimationFrame(tick)
    return () => window.cancelAnimationFrame(frameRef.current)
  }, [value, duration])

  return format(display)
}
```

Every other animated surface in this codebase checks a motion preference
somewhere — every CSS keyframe/transition of consequence has a
`prefers-reduced-motion` rule (`src/styles/modules/*.css`, 9 separate
blocks), and the one other JS-driven animation decision in the codebase,
`GrowthChart.jsx:182`, already gates itself on the media query:

```js
/* src/components/GrowthChart.jsx:182 — existing exemplar, for comparison only, do not edit this file */
if (navigator.vibrate && !window.matchMedia?.('(prefers-reduced-motion: reduce)').matches) navigator.vibrate(8)
```

`AnimatedNumber` is the one exception — a user who has explicitly asked for
reduced motion still gets a smooth 700ms interpolation on Portfolio's
"Invested value" headline (`src/pages/portfolio/Summary.jsx:132`, its only
call site) every time a price quote refreshes.

## Target

```jsx
/* target — src/components/AnimatedNumber.jsx */
import { useEffect, useRef, useState } from 'react'

// Animates a numeric value counting up or down to its new target whenever `value` changes,
// instead of the figure jumping straight to the refreshed number. Interpolates the raw
// number through requestAnimationFrame and hands each intermediate value to `format`, so a
// money/percent formatter can be reused as-is.
export default function AnimatedNumber({ value, format = String, duration = 700 }) {
  const [display, setDisplay] = useState(value)
  const fromRef = useRef(value)
  const frameRef = useRef(null)

  useEffect(() => {
    if (!Number.isFinite(value)) {
      setDisplay(value)
      fromRef.current = value
      return undefined
    }
    const from = Number.isFinite(fromRef.current) ? fromRef.current : value
    const reduceMotion = window.matchMedia?.('(prefers-reduced-motion: reduce)').matches
    if (from === value || reduceMotion) {
      setDisplay(value)
      fromRef.current = value
      return undefined
    }
    const start = window.performance.now()
    const tick = (now) => {
      const progress = Math.min(1, (now - start) / duration)
      const eased = 1 - (1 - progress) ** 3
      const next = from + (value - from) * eased
      setDisplay(next)
      if (progress < 1) {
        frameRef.current = window.requestAnimationFrame(tick)
      } else {
        fromRef.current = value
      }
    }
    frameRef.current = window.requestAnimationFrame(tick)
    return () => window.cancelAnimationFrame(frameRef.current)
  }, [value, duration])

  return format(display)
}
```

Two changes from current: a `reduceMotion` check added next to the existing
`window.performance`/`window.requestAnimationFrame` calls (same file already
reaches directly into `window`, so this matches its own style), and that
check folded into the existing early-return branch (`from === value ||
reduceMotion`) so the reduced-motion path reuses the exact same "jump
straight to the target" behavior the component already has for the
no-op case — no new code path, just a wider condition to reach it. Setting
`fromRef.current = value` in that branch (missing in the current `from ===
value` case, but needed here) keeps a later real change from computing a
`from` that's stale by more than one update.

## Repo conventions to follow

- `window.matchMedia?.('(prefers-reduced-motion: reduce)').matches` is the
  exact call already used in this codebase for a JS motion decision —
  `src/components/GrowthChart.jsx:182`. Copy that expression verbatim
  (including the optional-chaining on `matchMedia` itself, for
  test-environment/SSR safety where `matchMedia` may be undefined).
- Do not reach for `usePreferences()`'s `reducedMotion` setting
  (`src/lib/PreferencesContext.jsx`) — the existing `GrowthChart.jsx`
  exemplar deliberately checks only the OS-level media query, not the
  in-app three-state preference, and this plan matches that precedent
  rather than introducing a second convention.

## Steps

1. In `src/components/AnimatedNumber.jsx`, inside the `useEffect`, add
   `const reduceMotion = window.matchMedia?.('(prefers-reduced-motion:
   reduce)').matches` immediately after the existing `const from = ...`
   line.
2. Change the following `if (from === value) { ... }` condition to `if
   (from === value || reduceMotion) { ... }`.
3. Inside that `if` block, add `fromRef.current = value` before the
   existing `setDisplay(value)` (or after — order between the two doesn't
   matter, both must run).
4. Leave everything else in the file — the rAF loop, the easing curve, the
   `duration` prop, the JSDoc-style header comment — unchanged.
